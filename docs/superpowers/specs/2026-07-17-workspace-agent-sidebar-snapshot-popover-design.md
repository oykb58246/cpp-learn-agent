# 工作区 Agent 右栏与快照浮层设计

## 背景

当前工作区同时占用了两个与编辑器竞争空间的区域：快照常驻右侧栏，Agent 对话在编辑器下方展开。Agent 是学习过程中的高频交互入口，横向较窄但需要稳定的纵向阅读空间；快照主要服务于保存前留档、手动检查点和恢复操作，属于低频、按需使用的历史工具。现有布局把两者的视觉优先级放反了，也压缩了代码和底部问题面板的可用高度。

本设计将 Agent 对话移入现有右侧栏位置，并把快照改为从编辑器标签栏历史图标打开的浮层。快照的数据、自动创建时机、恢复和删除能力保持不变。

## 目标

1. Agent 对话显示在工作区右侧栏，不再占用编辑器下方空间。
2. 右侧 Agent 栏继续支持拖拽、键盘微调、双击复位和宽度持久化。
3. 快照不再常驻显示，通过保存按钮旁的历史图标按需展开。
4. 快照浮层不改变工作区网格宽度，也不遮挡右侧 Agent 对话。
5. 保留现有快照创建、恢复、删除、自动保存留档和项目元信息。
6. 在 1440x900 和 1024x720 窗口中保持代码区、Agent 标题区、消息区和输入区无重叠、无横向页面溢出。

## 非目标

- 不修改快照 IPC、数据库结构、清理策略或保存前快照语义。
- 不把快照升级为完整版本控制或文件级差异浏览器。
- 不修改 Agent 对话、审批、运行时间线、错误收件箱或模型调用的数据流。
- 不迁移或重命名设置存储中的 `inspectorWidth` 字段。
- 不调整底部“输出 / 问题 / 调试”面板的业务功能。

## 已确认的产品决策

- 采用“Agent 常驻右栏位置，工具栏历史按钮弹出快照”的方案。
- Agent 按钮继续控制右侧栏的显示和隐藏；关闭后编辑器占用释放出的宽度，不保留空白栏。
- 快照浮层位于编辑区域右上角。Agent 打开时，浮层仍限制在编辑区域内，出现在 Agent 左侧。
- 快照浮层支持再次点击历史按钮、点击浮层外部、按 `Escape` 和点击关闭图标四种关闭方式。
- Agent 与快照浮层可以同时打开。
- 项目切换时关闭快照浮层，避免旧项目的短暂内容残留。

## 布局结构

工作区继续使用三列网格：文件侧栏、编辑区域、可选右侧栏。第三列的内容从快照检查器改为 Agent 对话，是否存在由 `agentOpen` 控制。

```text
workspace-view
  workspace-sidebar
  editor-area
    editor-tabs
      save
      snapshot history trigger
    snapshot-popover (overlay, optional)
    editor-toolbar
    editor-surface
    bottom-panel
  workspace-agent-inspector (optional)
    ConversationPanel
```

关闭 Agent 时，网格切换为文件侧栏加编辑区域两列。原有右侧栏宽度、分隔条和调整逻辑继续使用 `inspectorWidth` 与 `ResizeTarget = 'inspector'`，只更新界面名称和无障碍标签为 Agent 侧栏。这样保留现有设置兼容性，不需要数据迁移。

## Agent 右侧栏

`ConversationPanel` 继续作为唯一 Agent 会话组件，沿用当前的对话选择、新建、归档、消息流、审批、工具运行状态、错误状态和 composer 事件。`WorkspaceView` 只改变组件挂载位置，不复制会话逻辑。

右栏使用完整可用高度，内部纵向分配为：

1. 标题与对话命令区。
2. 可选审批或运行证据区。
3. 可滚动消息记录区。
4. 固定在底部的输入区。

在较窄的右栏中，标题和命令区允许分为两行；对话选择器占用剩余宽度。Composer 的模式选择器单独占一行，文本框与发送/停止按钮位于下一行。运行证据从并排布局降级为纵向布局。任何动态状态不得改变右栏整体宽度。

Agent 工具栏按钮保留现有的错误数量徽标和注意动画。存在错误收件箱时，按钮仍优先打开错误收件箱；用户从收件箱发起讲解后，Agent 右栏自动打开。

## 快照浮层

新增 `SnapshotPopover` 组件，承接当前快照侧栏中的快照相关 UI。组件接收快照列表和当前项目信息，并通过事件请求创建、恢复、删除和关闭；实际 store 操作仍由 `WorkspaceView` 执行。

浮层行为：

- 锚定在编辑区域右上角，位于标签栏下方，宽度受编辑区域约束。
- 使用固定最大高度，快照列表在内部滚动，不扩大工作区。
- 历史图标具有打开状态样式，并提供 `aria-expanded`、`aria-controls` 和明确的工具提示。
- 浮层使用对话框语义和可见标题；创建输入保留键盘回车提交能力。
- 恢复与删除沿用现有图标按钮和提示文案。
- 项目元信息保留在快照列表下方，随浮层按需显示。
- 空列表继续显示现有的快照用途提示。

外部点击监听只在浮层打开时注册，关闭或组件卸载时移除。历史按钮和浮层内部阻止该关闭事件误触发，确保点击触发器可以稳定切换开关。

## 状态与数据流

`WorkspaceView` 使用两个互不排斥的界面状态：

- `agentOpen`：控制 Agent 右侧栏和其分隔条。
- `snapshotOpen`：控制快照浮层。

原 `inspectorOpen` 被移除，避免一个状态同时表达两种面板含义。`inspectorWidth` 继续从设置加载和保存，仅作为兼容的宽度字段名。

快照创建数据流保持为：

```text
SnapshotPopover create event
  -> WorkspaceView.snapshot(label)
  -> workspace store.createSnapshot(label)
  -> existing snapshots IPC
  -> refreshSnapshots()
  -> updated props render in popover
```

恢复和删除同样调用现有 store 方法。错误继续写入 `workspace.error`，由现有全局错误提示呈现；组件不维护第二份错误状态。

## 响应式与可访问性

- 右侧栏使用现有 220 至 480 像素宽度范围，并继续保证编辑区域最小宽度。
- 1024 像素窗口下通过现有宽度夹取逻辑缩小文件栏或 Agent 栏，不产生页面级横向滚动。
- 快照浮层宽度使用视口和编辑区域双重约束；窄编辑区中不超出其父区域。
- Agent 右栏分隔条的 `aria-label`、标题和双击说明全部改为 Agent 语义。
- 历史图标、关闭、创建、恢复、删除均保留可读名称和键盘可操作性。
- 浮层打开时不抢占编辑器焦点；用户主动聚焦创建输入后可正常键入。按 `Escape` 仅关闭浮层，不关闭 Agent。

## 测试策略

### 组件与单元测试

- `SnapshotPopover` 渲染快照、空状态和项目元信息。
- 创建事件对空标签使用“手动快照”，非空标签保留去除首尾空格后的文本。
- 恢复、删除和关闭按钮发出正确事件。
- `Escape` 与外部点击关闭，内部点击不会关闭。

### E2E

- 打开 Agent 后 `.conversation-panel` 位于右侧栏中，编辑区域下方不再存在 Agent 面板。
- Agent 关闭后第三列和分隔条消失，编辑器扩展占用空间。
- 历史按钮打开快照浮层，再次点击、外部点击和 `Escape` 均能关闭。
- 保存文件仍增加自动快照；手动创建、恢复和删除仍可用。
- Agent 右栏宽度拖拽后仍写入并恢复 `inspectorWidth`。
- 1440x900 与 1024x720 截图中，Agent 标题命令、消息、composer、快照浮层和底部面板没有重叠，文档根节点无横向溢出。

## 验收标准

1. 用户点击 Agent 后，对话仅在右侧栏出现；关闭后右栏完整收起。
2. 底部面板只包含输出、问题和调试，不再被 Agent 对话占用高度。
3. 快照仅在用户点击历史图标后可见，并能通过四种约定方式关闭。
4. 快照浮层和 Agent 可同时使用，浮层不遮挡 Agent。
5. 原有快照创建、自动保存留档、恢复、删除和项目元信息没有功能回归。
6. 原有 Agent 对话、审批、错误讲解、停止和重试没有功能回归。
7. 右侧栏尺寸调整继续持久化，现有设置无需迁移。
8. 类型检查、相关单元测试和 E2E 通过，两个目标窗口尺寸无溢出或控件重叠。
