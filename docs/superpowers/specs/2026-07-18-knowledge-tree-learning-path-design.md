# 知识树学习路径设计

## 目标

优化桌面端知识树，使用户能直接理解知识点的先后依赖和并列关系，并在节点上更新自己的掌握状态。该改动不引入新的学习数据模型或 IPC 接口。

## 范围

- 将按分类平铺的知识点列表改为阶段泳道布局。
- 将状态收敛为未学习、学习中、已掌握三种。
- 在每个节点上直接提供状态切换按钮。
- 移除知识树视图的“编辑背景”入口。
- 保留已有的前置依赖校验与错误反馈。

重点解释标记不在本次改动范围内，现有背景档案编辑能力不改变。

## 视觉与关系模型

知识树以知识点的 `category` 为泳道。泳道从左到右按目录中首次出现的分类排序，并在标题中显示阶段序号。

- 同一泳道内，单个节点纵向排列；相邻节点之间以向下箭头表达顺序。
- 处于相同依赖层级、且没有彼此依赖的知识点，在同一层以内联双列卡片表示并列关系。
- 对于跨泳道的依赖，目标节点显示“前置”标签，标签列出对应知识点标题。必要时以低干扰的虚线连接补充方向；布局不能因为连线遮挡节点内容。
- 卡片左侧状态色、状态标签和顶部图例共同表达状态：灰色为未学习，蓝色为学习中，绿色为已掌握。

布局首先服务可扫描性。较小窗口下应横向滚动泳道区域，避免压缩卡片或隐藏状态操作。

## 节点交互

每张知识点卡片包含标题、简要描述、前置标签和固定高度的三段状态操作：未学习、学习中、已掌握。

- 当前状态按钮高亮。
- 三态映射到现有状态模型：未学习为 `locked`，学习中为 `learning`，已掌握为用户自报的 `self-claimed`；不会在本视图写入 `review` 或 `verified`。
- 已满足全部前置条件时，三个操作均可用；点击后调用现有 `agent.updateKnowledge(conceptId, status)`。
- 未满足前置条件时，未学习仍可用，学习中和已掌握禁用。卡片显示缺失的前置知识点。
- 请求失败或运行时再次拒绝状态变更时，保持当前 UI 状态并使用现有错误反馈展示原因。
- 不展示“待复习”，也不向状态更新接口传递该值。

“编辑背景”按钮从知识树工具栏移除。背景档案弹窗及其重点解释设置不在此视图中触发。

## 数据与实现边界

视图继续读取 `agent.catalog` 的图谱节点以及 `agent.knowledge` 的用户状态。依赖关系来自每个节点的 `prerequisites`，状态更新沿用已有 store action 与主进程 `transitionKnowledge` 校验。

前端只负责计算展示层级、分类泳道和禁用条件；主进程仍是前置条件的最终裁决者。运行时状态迁移调整为允许任意节点重置为 `locked`，并允许已满足前置条件的节点直接进入 `self-claimed`。无需改动数据库 schema、预加载桥接层或 IPC 合约。

## 验证

- 单元或组件测试覆盖分类排序、依赖层级/并列分组和三态可选性。
- E2E 覆盖知识树加载、阶段泳道与前置标签可见、状态按钮可操作，以及前置不满足时状态操作不可用。
- 保留或更新现有知识树基础断言，验证不再出现“编辑背景”和“待复习”。
- 执行 renderer 类型检查、桌面端构建和受影响的 E2E 测试。
